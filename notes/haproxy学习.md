反向代理 Haproxy

# HAProxy 介绍
HAProxy 是一款高性能、专业的四层/七层负载均衡、反向代理开源软件。
核心定位：只负责流量转发、调度、健康检查，不做静态资源、不做页面服务。
业界公认：最稳定、最适合后端集群的负载均衡器，大量金融、微服务、数据库集群使用。

# 两大代理模式
- 四层 TCP 负载均衡：基于 IP+端口转发，不解析应用层，性能极高，适合长连接服务（MySQL、Redis、MQ）
- 七层 HTTP/HTTPS 负载均衡：完整解析 HTTP 协议，可基于 URL、Cookie、Header 做精准路由、灰度、流量分发

# HAProxy 核心核心特性
## 原生支持七层主动健康检查
这是 HAProxy 和 Nginx 最大区别。
- HAProxy：主动定时探测后端接口/端口，服务挂了立刻剔除，无需用户报错
- Nginx 开源版：只有被动健康检查，用户访问报错后才剔除节点
生产意义：HAProxy 可以实现业务零报错摘除故障节点，适合核心业务。

## 丰富的负载均衡算法
- roundrobin：权重轮询（短连接默认）
- leastconn：最少连接（长连接 MySQL/Redis 首选）
- source：源 IP 哈希，实现会话保持
- uri：URL 哈希，适合静态缓存集群
- 支持自定义权重、慢启动、熔断、重试、队列

## 自带可视化监控面板 stats
无需插件、无需部署监控，直接开启 /stats 页面：
- 实时查看所有后端节点在线/离线状态
- 连接数、QPS、错误数、重试次数
- 批量手动上下线节点

## 强大的 HTTPS 能力
- 统一 SSL 证书卸载，后端全部 HTTP
- 支持证书动态更新、多种加密协议、安全策略

## 高可用必须依赖 Keepalived
HAProxy 本身无心跳、无集群、无 VIP 漂移能力。
生产高可用架构：HAProxy + Keepalived（VRRP）
由 Keepalived 负责：心跳检测、进程监控、VIP 漂移、故障切换。

# 示例
客户端 --> VIP(Keepalived) --> HAProxy --> 后端服务集群
- Keepalived：解决代理层单点故障、VIP 漂移
- HAProxy：四层/七层负载均衡、主动健康检查、流量调度

# HAProxy 优缺点
## 优点
- 七层原生主动健康检查（核心优势）
- 四层 TCP 长连接负载均衡极其稳定
- 负载均衡算法丰富，适合各种复杂业务
- 自带监控面板，运维友好
- 性能强、延迟低、稳定性极高，适合核心金融级业务

## 缺点
- 不擅长静态资源处理（无文件缓存、无强大静态处理模块）
- 不能作为 Web 服务器使用
- 自身无高可用，必须依赖 Keepalived

# HAProxy VS Nginx 
- **HAProxy**：专业负载均衡/反向代理软件，**专注流量分发**。四层TCP、七层HTTP都很强。不是Web服务器，不擅长处理静态文件。
- **Nginx**：Web服务器 + 反向代理 + 负载均衡。**主打HTTP服务、静态资源、缓存**，附带负载均衡能力。

| 对比项           | HAProxy                                                                    | Nginx（开源版）                                                              |
| ---------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 七层HTTP健康检查 | ✅ **主动健康检查**，定时探测后端接口，故障节点提前下线，不需要用户请求触发 | ❌ **被动健康检查**，只有请求打到后端返回错误，才标记节点故障；会出现用户报错 |
| 四层TCP负载均衡  | 原生支持，长连接（MySQL/Redis）稳定性优秀                                  | 需要`stream`模块，支持，但不是原生强项                                       |
| 负载均衡算法     | 丰富：轮询、最少连接、源IP哈希、URL哈希等                                  | 基础：轮询、ip_hash、least_conn，算法较少                                    |
| 静态资源处理     | 很差，不支持本地文件服务、缓存                                             | 极强，静态文件、gzip压缩、浏览器缓存、防盗链、限速                           |
| 监控面板         | 内置`/stats`页面，直接查看节点、连接、错误指标                             | 无原生监控页面，需要第三方脚本/Exporter采集                                  |
| HTTPS能力        | 支持证书卸载，适合集中网关                                                 | HTTPS性能优秀，证书配置灵活                                                  |
| 会话保持         | 多种方式（cookie插入、源ip）                                               | ip_hash实现会话保持                                                          |

## 选 HAProxy
1. 后端微服务、API集群负载均衡，不允许用户遇到报错才摘除故障实例
2. TCP长连接服务负载均衡：MySQL、Redis、RabbitMQ
3. 内网流量入口，需要精细化流量调度、权重、灰度发布
4. 需要直观页面监控后端节点状态

## 选 Nginx
1. 外网网站、前端页面，大量静态资源（html/js/css/图片）
2. 需要缓存、gzip压缩、防盗链、限流、动静分离
3. 直接对外提供Web访问，前端项目部署

## 架构搭配
```
外网用户 → Nginx（外网入口，静态资源、压缩、防攻击）
        → HAProxy（后端集群负载均衡、主动健康检查）
        → 微服务/数据库
```
> 分工：Nginx扛外网和静态资源；HAProxy负责内网后端服务流量分发。

两者本身都**没有VRRP、不能自动VIP漂移**。
做高可用，都需要搭配 **Keepalived**，依靠VRRP协议实现VIP漂移、主备故障切换。
